# Contributor Code of Conduct

Short on purpose. This is a small project run by one person, and a four-thousand-word
policy would not be read by anyone, including me. So this is the actual expectation.

## Be decent to people

Assume good intent. Respond to the substance of a comment, not the tone you think you
detect in it. Nobody here is being paid to review your pull request, and the fact that a
change has been waiting a week is not evidence of disrespect.

## Be decent to the work

- Say what you actually tried. "Tests pass" when the integration suites skipped for want of
  a database is a misleading claim, and correcting it costs one sentence.
- Disagreement about design is welcome. Do not describe a preference as a rule.
- Do not pretend to know. If you are guessing about why a lock exists or what a ticket
  covers, say you are guessing; confident wrongness is the most expensive thing a
  contributor can produce, and this project has been bitten by it before.
- Keep other people's private information private. This is software that runs against
  someone's media library and account data.

## What happens if it goes wrong

The first instance is a conversation, not a sanction. Persistent behaviour that makes people
unable to contribute gets a private word from the maintainer, and if that fails, the
option to stop contributing here exists and will be used.

Nothing about this project's licensing, governance or future changes based on your identity,
and disagreement with a technical decision has never been grounds for exclusion here.

## Scope

Repository spaces: issues, pull requests, commits, and direct contact about the project.
Offline conduct is out of scope, though using this project to harm people is not.

## Reporting

Open a [private security advisory](https://github.com/FNXDOOM/Animind_Desktop_Backend/security/advisories/new)
or contact the maintainer through GitHub. Reports are read by one person, so expect that
response is honest and may be slow rather than institutional. If you would prefer not to
raise something with the maintainer at all, GitHub's own reporting for
[abuse or conduct violations](https://docs.github.com/en/site-policy/content-communities-policies/github-community-code-of-conduct)
covers behaviour on GitHub regardless of this file.

This project is maintained by one person. That is disclosed rather than hidden, because it
changes what "we will look into it" realistically means.
